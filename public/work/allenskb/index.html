Case study 02  /  Allen's Cabinets

allenskb.com

The public site for a kitchen and bath showroom in Alexandria, Virginia. It replaces an old WordPress site, and it has one job: turn someone looking at kitchen photos into a showroom visit or a quote request. Every booking and inquiry goes into the same Postgres database the staff admin tool reads from.

§01 Visitor flow 06 STEPS
01 — /

Land on the kitchen, not the logo

The old / was a splash screen that gated into /home — no body copy and no crawlable link. Now it is the real homepage: a full-bleed project photo, the two actions that matter, and count-up figures driven by IntersectionObserver so they animate when you actually reach them.

02 — /cabinets

Browse by product

Cabinets, countertops and handles each get their own page, with the product lines, lead times and a way to book on every one. Each route is prerendered to its own HTML file with its own title, canonical URL and Open Graph card, so a shared link previews the right page.

03 — /gallery

See the finished work

A masonry gallery of completed projects, filterable by kitchen, bathroom and countertop, with a lightbox. The staff publish projects from the admin tool, and the build pulls a snapshot from Supabase — so the gallery is in the static HTML and loads without a database round trip. A failed fetch fails the build rather than shipping an empty gallery.

04–05 — Booking modal

Book a showroom visit in three steps

Date, then time, then name and email. The calendar shows only open days, and each time slot allows two bookings. A Postgres trigger enforces that limit, so two people picking the last slot at the same moment can't both get it. The confirmation email links to a token-scoped page where the customer can cancel or reschedule without making an account.

06 — /contact

Or ask for a quote, with photos

The quote form takes up to four photos of the room. They are resized in the browser to 1600 px, with EXIF rotation applied, so they fit under Vercel's 4.5 MB request limit. They are attached to the notification email and never stored — the business asked for no photo retention.

§04 Engineering notes
SEO

Static HTML for crawlers that don't run JavaScript

Before prerendering, every route shipped an empty <div id="root"> and the homepage's share card. Bing, AI crawlers and link previews (iMessage, Slack) read the raw HTML, so each page now carries its real words and meta tags at build time.

Migration

39 old URLs, none of them lost

Every URL from the WordPress site — yearly project pages, deal pages, /showroom, /faqs — has a permanent 301 to its closest new page, so existing search rankings and bookmarks carry over.

Concurrency

The database enforces the booking limit

The UI hides full slots, but that's only for display. A BEFORE INSERT trigger is what enforces the two-per-slot limit, and the availability RPC returns only slot counts — never names or emails.

Privacy

Visitor counts with no cookies

Page views and conversions go through a serverless function that hashes IP, user agent and the day together with a salt, and saves only the hash. The hash changes daily, so nobody can be followed from one day to the next, and there's no cookie banner. Bots, Do Not Track and GPC requests are ignored.
